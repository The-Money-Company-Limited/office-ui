# Mammoth coverage

This is a source-content audit against Mammoth 1.12.0, its retained README, and its retained test suite. It is not a claim of drop-in converter compatibility or Word layout parity. The shared Rust model is used by native consumers and WASM; the block API adds source identity and geometry that is resolved later by the viewer.

The current Extend converter calls `mammoth.convertToHtml`, replaces image sources with an empty string, and chunks the resulting HTML. Its reported pages are HTML chunks. Replacing it with structured blocks therefore needs an adapter and a real pagination result; the current Rust API does not implement the same HTML converter signature or its options.

## Current evidence

- The final upstream fixture rerun matches normalized Mammoth body text in **17/17** documents. The text-box fixture contains its text once. This checks text retention, not every property of those documents.
- Eight native regressions cover capitalization inheritance and serialization, paragraph-mark edits, nested/split/intra-run hyperlink fields, deleted rows and merge spans, repeated/interleaved images, and Unicode textbox/AlternateContent source positions.
- Three focused TypeScript test files passed eight checks. Actual Chromium checks cover 12 uppercase combinations of font size, letter spacing, and narrow wrapping, plus normal/small-caps text. Original text and UTF-16 offsets are retained, including uppercase expansion. In that unscaled browser check, maximum fragment-width difference was below 0.040 px and caret difference below 0.038 px.
- A full `DocxEditorViewer` smoke check preserves source text and produces the same eight line endings and widths as an explicitly uppercase reference at 50% and 100% zoom. At 100%, small-caps DOM width differs from canvas by 0.004 px. At 50%, Chromium's synthetic small caps changes its unscaled glyph width, so that zoom case remains a geometry limitation. These are browser rendering checks, not native Word comparisons.
- The retained 1,000-document parser pass parsed all 1,000; Mammoth read 997. Of those, 934 match after ignoring whitespace and 967 retain Mammoth's characters in order. All 30 remaining reading-order differences retain every exact paragraph occurrence in the structural audit, including duplicate counts. There were no duplicate block IDs or mismatched document bindings. Flat-text differences can arise when a floating textbox interrupts a parent paragraph; the structural audit also excludes checkbox objects as Mammoth raw-text extraction does. These are content checks, separate from page/geometry comparison.

Retained evidence is under `output/playwright/structured-blocks/mammoth-coverage/`: `upstream-fixtures-final.json`, `caps-browser-result.txt`, `viewer-summary.json`, and `semantic-retention-audit.json`. The final upstream fixture rerun after optional word-span support and default table-style selection records WASM SHA-256 `e7b28fafc0e02d8d2964688fba905b88e395a6967d8ee0ac8d969dd7b63eb767`; the corpus audit and preceding fixture run pin `1c1edc273ef6093bca8c229976b57ba3dd74bab978e42ae83991e8079381db7c`. Later builds should rerun checks rather than inherit this claim.

## Content and semantics

| Upstream feature area | Current shared model / blocks | Remaining boundary |
| --- | --- | --- |
| Paragraphs, text, nested content | Paragraph/run content, alignment, indentation, spacing, source IDs and UTF-16 inline ranges are retained. Tables and textboxes are traversed. Automatic before/after spacing flags preserve inheritance and explicit false, including legacy DOC import and DOCX serialization. | The block API intentionally filters empty content. It does not reproduce Mammoth's optional empty-HTML-paragraph behavior. Table-cell automatic edge suppression is implemented from native controls; ordinary interior automatic spacing and all HTML compatibility combinations are not fully resolved. |
| Headings and named paragraph styles | Paragraph style IDs, style definitions/names, resolved formatting, and heading classification are available. | Heading classification is limited to model-supported levels. Custom mappings from arbitrary style names to HTML elements are converter features and are absent. |
| Character and table styles | Resolved character formatting and table style data are used for rendering. | Individual text runs do not expose character-style ID/name. Duplicate-style precedence and every malformed-style fallback from upstream tests are not equivalent or exhaustively verified. |
| Lists and numbering | Paragraph numbering IDs/levels, abstract and instance definitions, ordered/bullet formats, start overrides, and viewer markers are supported. | Blocks retain numbering metadata, but their formatted/Markdown preview does not reconstruct list containers or markers. Missing `w:ilvl` on numbering definitions is not handled like Mammoth's level-zero fallback. Numbering-style indirection and duplicate-level edge cases are not fully equivalent. |
| Tables, nested tables, headers, colspan/rowspan | Structured tables, header groups and cells retain content, physical grid indices, spans, and styles. Nested tables are retained. | Empty cells can be represented by grid metadata rather than separate nonempty blocks. Full malformed-grid/error-message compatibility is not established. |
| Deleted table rows | Direct tracked-deleted rows are omitted before calculating visible merge spans. | Original XML retains those rows, but a complete show-deleted-row rendering mode is not implemented. |
| Bold, italic, underline, strike | Run formatting is retained and shown by the viewer and rich block preview. | The preview simplifies underline/strike variants. Mammoth ignores underline by default unless mapped; this viewer preserves it. |
| Superscript, subscript, font, size | Run properties are retained; the viewer and preview apply them. | Font substitution and metrics remain rendering dependencies. A retained property does not establish Word glyph or baseline parity. |
| Highlight and color | Highlight, foreground/background color and additional run formatting are retained; preview and Markdown-with-HTML preserve them. | The preview's named-color palette is simplified. Mammoth's highlight style-map selectors are not exposed. |
| All caps and small caps | Both flags now survive inherited/direct formatting, native/WASM models, block inlines, serialization, viewer measurement and rendering. All-caps measurement preserves original source strings and offset boundaries. | Approximate SVG textbox fallback does not yet apply these flags. Small-caps synthesis depends on browser/font/zoom; the former snapshot renderer is not covered by the main viewer checks. |
| Tabs, no-break/soft hyphens | Source characters are retained. The viewer handles tabs; inline source offsets include them. | Mammoth raw-text output and visual tab layout are separate contracts. |
| Symbols | Symbol-font mappings provide Unicode content for supported symbol sets. | Unsupported symbols have different fallback/diagnostic behavior. Every upstream mapping is not independently visually verified. |
| Explicit text hyperlinks | Relationship URLs and internal anchors are retained. An explicit anchor replaces an existing URI fragment. | `targetFrame` is not a first-class run property. The block preview uses its own link policy and target. |
| Complex hyperlink fields | Quoted/unquoted targets, split instructions, nested fields, and scope changes inside a single run now preserve links. Source byte positions avoid shifted links after empty tokens, textboxes, or AlternateContent. | Arbitrary Word field evaluation is not implemented. Cached field values are the main content source. |
| Image hyperlinks | Drawing/image source XML is retained. | `a:hlinkClick` and image-level hyperlink semantics are not first-class `ImageRunNode`/figure fields. This is a Mammoth semantic gap. |
| Bookmarks | Source XML is retained; the viewer resolves bookmark navigation from it. | Structured blocks do not expose first-class bookmark names/ranges or Mammoth-style HTML anchor IDs. |
| Line/page/column breaks | Visible line breaks are retained; the viewer also reads explicit page/column break semantics from source XML. | Block inlines do not distinguish all break kinds. Mammoth's raw-text extractor ignores break objects, while its HTML converter emits line breaks. Exact raw-text serialization is not an API promise here. |
| Footnotes and endnotes | Note IDs, references and full note stories are retained, including note-local relationships. | Mammoth's generated HTML backlink/ID scheme is not implemented. Native Word note pagination still needs independent validation. |
| Comments | Comment stories and metadata are retained; the viewer reads source comment ranges and can show annotations. | Structured inlines do not yet expose comment-reference/range objects. Author/initials normalization and Mammoth's mapped HTML comment layout are not equivalent API behavior. |
| Inline, floating, VML and linked images | Embedded assets, alt text, dimensions, crop, floating properties and content type are represented. Figure previews use the actual asset. Repeated occurrences and text/image order within a run are retained. | Several images/shapes inside one outer drawing/picture can be represented by one composite/fallback node; per-image semantic parity there is unverified. External-file reading callbacks and Mammoth image-reader APIs are absent. |
| Image formats and alternate assets | Native image assets are preserved; supported browser/conversion fallbacks render common image types. | Asset retention does not prove every codec or vector feature renders identically. Mammoth's warning strings and MIME allowlist are not the viewer's contract. |
| Textboxes and shapes | Textboxes have nested paragraph/table content with source IDs, and figures can expose child blocks. The upstream textbox body text now matches once. | Mammoth appends textbox content after the containing paragraph; the model preserves nesting/occurrence order. Approximate SVG shape/text fallbacks are not full Word drawing layout. |
| AlternateContent | Preferred Choice content is normalized before source positions are assigned; nested fallbacks are not duplicated. | Mammoth normally reads Fallback. Documents with different Choice/Fallback content can intentionally produce different supported representations. |
| Inserted/deleted content and deleted paragraph marks | Inserted content, revision source XML and paragraph-mark deletion metadata are retained. Visible deleted text is excluded from normal extraction. | Blocks can retain separate paragraph identities where Mammoth joins paragraphs across a deleted mark. Complete move/deletion/revision-view equivalence is not established. |
| Content controls and legacy form fields | Structured content is traversed; supported checkbox/text/date/dropdown controls expose structured key-value metadata. | Mammoth's checkbox objects disappear from its raw-text extraction; our visible block content can include their glyphs. Every unsupported control subtype is not guaranteed to have a dedicated semantic type. |
| Smart tags, objects and wrapper elements | Supported descendant content and original package/XML parts are preserved. | Preserved OLE/embedded/unknown content is not necessarily parsed into first-class blocks or rendered. |
| Package main part, relationships, strict namespaces, BOM/UTF-16 | Relationship-selected parts, relative targets, strict namespace normalization and supported XML encodings are handled. | All malformed ZIP/XML recovery, missing-part errors and URI edge cases from Mammoth are not promised to match. Password/encryption handling belongs to the import boundary. |
| Unknown elements and warnings | Preserved-source inspection exposes unsupported/approximate feature diagnostics and unknown parts/assets. | Warnings are not Mammoth `Result.messages`; retaining XML is not equivalent to understanding or rendering its semantics. |

## Converter and public API boundary

The following upstream areas were audited as API/conversion behavior, not implemented as compatibility features: `convertToHtml`/deprecated `convertToMarkdown`/`extractRawText` signatures; explicit/default/embedded style maps and map embedding; HTML-path matching (`fresh`, wrappers, separators, selectors, collapsible runs and lists); `transformDocument` and transform helpers; `convertImage`, `images.imgElement`/`inline`/`dataUri`, and asynchronous image-reader helpers; `idPrefix`; `ignoreEmptyParagraphs`; `includeDefaultStyleMap` and `includeEmbeddedStyleMap`; external-file access options; pretty printing; result warning/error combination; CLI input/output-directory behavior; and HTML/Markdown writer escaping/simplification rules. The block preview is a display of structured results, not a replacement implementation of those converters.

Retained upstream test areas accounted for here are `docx/body-reader`, `document-xml-reader`, `docx-reader`, `styles-reader`, `numbering-xml`, `notes-reader`, `comments-reader`, `relationships-reader`, `content-types-reader`, `office-xml-reader`, `files`, `uris`, and `style-map`; `document-to-html`, `images`, `raw-text`, `mammoth`, `main`, `options-reader`, `results`, `transforms`, and `style-reader`; `styles/document-matchers`, `styles/html-paths`, and `styles/parser/tokeniser`; `html/simplify`, `html/write`, `writers/html-writer`, `writers/markdown-writer`; and `unzip`, `zipfile`, `xml/reader`, and `xml/writer`. Test helper modules contain supporting assertions rather than additional product capabilities. The entire upstream test suite has not been run against this different API.

The next semantic gaps are typed inline bookmarks/comments/breaks, image hyperlinks, character-style identity, list reconstruction in block previews, and remaining numbering indirection/defaults. Converter compatibility should be a separate adapter decision. Word page count, break placement, drawing layout and bounding rectangles require the independent native-reference and browser geometry checks described in `structured-blocks.md`.
